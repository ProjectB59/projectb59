B59-102.001 · WRITING · HASH FUNCTIONS

The MD5 Message-Digest Algorithm (RFC 1321)

Ronald L. Rivest · Network Working Group, RFC 1321 · April 1992
"The algorithm takes as input a message of arbitrary length and produces as output a 128-bit fingerprint or message digest of the input."

Why it matters

Cryptographic hash functions are the workhorse primitive of everything the cypherpunks built next: proof-of-work, hash chains, Merkle trees, commitment schemes, content addressing. MD5 was, through the 1990s and 2000s, the default one. This RFC is how it was specified and spread.

What it specifies

A padding rule, a 128-bit state, and four rounds of 16 operations mixing the message into that state, plus a full reference implementation in C. The "conservative" design note explains that MD5 deliberately traded some of MD4’s speed for a wider security margin.

Reading it now

Collisions in MD5 were demonstrated in 2004 and made cheap thereafter, and it must not be used where collision resistance matters (certificates, signatures). It survives as a fast non-security checksum and as a case study in how hash functions fail. The RFC is kept here as the historical record, not as a recommendation.

Executive summary (verbatim)

This document describes the MD5 message-digest algorithm. The algorithm takes as input a message of arbitrary length and produces as output a 128-bit "fingerprint" or "message digest" of the input. It is conjectured that it is computationally infeasible to produce two messages having the same message digest, or to produce any message having a given prespecified target message digest. The MD5 algorithm is intended for digital signature applications, where a large file must be "compressed" in a secure manner before being encrypted with a private (secret) key under a public-key cryptosystem such as RSA. ... The MD5 algorithm is being placed in the public domain for review and possible adoption as a standard.
